MEGASPORT - DOCUMENTACION DEL FRONTEND
======================================
Fecha de esta documentacion: 2026-09-20
Proyecto: MegaSport - Tienda virtual de ropa y calzado deportivo
Fase documentada: Frontend funcional con datos y servicios simulados


1. OBJETIVO GENERAL DEL FRONTEND
--------------------------------
MegaSport es la interfaz web de una tienda virtual de ropa deportiva. En esta fase el frontend ya permite recorrer practicamente todo el flujo de compra, pero todavia no existe una base de datos real ni un backend Node.js conectado.

Actualmente la aplicacion puede:

- Mostrar una pagina principal con categorias y productos destacados.
- Navegar por categorias: Hombre, Mujer, Ninos y Zapatos.
- Mostrar el detalle de un producto.
- Permitir seleccionar una variante especifica del producto segun talla y color.
- Respetar el stock disponible de cada variante.
- Agregar variantes al carrito y modificar sus cantidades.
- Mantener el carrito aunque se recargue el navegador mediante localStorage.
- Crear un borrador de orden a partir del carrito.
- Capturar direccion y codigo de destino.
- Simular consultas a tres couriers y obtener cobertura y costo de envio.
- Permitir seleccionar un courier y calcular el total con envio.
- Detectar el proveedor de una tarjeta por el primer digito.
- Simular una autorizacion de pago APROBADA o DENEGADA.
- Formalizar una orden cuando el pago es aprobado.
- Simular la solicitud de un envio al courier elegido.
- Obtener un numero de envio y consultar su estado.
- Mostrar una pantalla final de confirmacion y seguimiento de la orden.

Esta implementacion fue preparada de forma que la mayor parte de la interfaz pueda conservarse cuando se agreguen el backend y la base de datos. Los archivos dentro de src/data y src/services contienen buena parte de la simulacion que posteriormente debera reemplazarse por llamadas HTTP al backend.

4. FLUJO GENERAL DE LA APLICACION
---------------------------------
El flujo de compra actual es aproximadamente:

Inicio
  -> Categoria
  -> Detalle del producto
  -> Seleccion de variante (color/talla)
  -> Carrito
  -> Crear borrador de orden
  -> Datos de entrega
  -> Consulta y seleccion de Courier
  -> Pago
  -> Autorizacion de tarjeta
  -> Solicitud de envio
  -> Formalizacion de orden
  -> Confirmacion y seguimiento

Rutas implementadas:

/                         Pagina principal
/categoria/:category      Catalogo filtrado por categoria
/producto/:id             Detalle de un producto
/carrito                  Carrito de compras
/checkout                 Captura de direccion y destino
/checkout/courier         Consulta y seleccion de courier
/checkout/pago            Pago y autorizacion
/orden/:id                Confirmacion y seguimiento de una orden
*                         Pagina 404 para rutas inexistentes

6. src/main.tsx
---------------
Es el punto de entrada de React.

Funciones principales:
- Obtiene el elemento HTML con id "root".
- Crea la raiz de React con createRoot().
- Envuelve la aplicacion con BrowserRouter para habilitar React Router.
- Envuelve App con CartProvider para hacer accesible el carrito globalmente.
- Envuelve App con OrderProvider para hacer accesible el estado de checkout y orden globalmente.

Estructura conceptual:

BrowserRouter
  -> CartProvider
      -> OrderProvider
          -> App

No recibe parametros externos ni retorna datos a otros archivos; simplemente inicializa la aplicacion.


7. src/App.tsx

Responsabilidades:
- Muestra Navbar en la parte superior.

- Muestra Footer al final.
- Mantiene un layout de altura minima de pantalla.

Entradas:
- La URL actual, gestionada internamente por React Router.

Salida:
- Renderiza el componente de pagina correspondiente.

11. CARPETA src/context
-----------------------
Los contextos contienen estado global compartido por distintas paginas.

11.1 CartContext.tsx
--------------------
Gestiona el carrito.

Estado principal:
items: CartItem[]

Persistencia:
- Guarda y recupera el carrito en localStorage con la llave:
  megasport-cart

Funciones expuestas:

addItem(idVariante, cantidad, stockDisponible)
  Entradas:
  - idVariante
  - cantidad solicitada
  - stock disponible

  Procesamiento:
  - Rechaza cantidad <= 0 o stock <= 0.
  - Si la variante ya existe en el carrito, suma cantidades.
  - Usa Math.min para impedir superar el stock.
  - Si no existe, crea un nuevo CartItem.

  Salida:
  - Actualiza items del contexto.

updateQuantity(idVariante, nuevaCantidad, stockDisponible)
  - Si nuevaCantidad <= 0 elimina el item.
  - De lo contrario actualiza cantidad sin superar stock.

removeItem(idVariante)
  - Elimina del arreglo la variante indicada.

clearCart()
  - Vacia todos los items.

 totalItems
  - Valor calculado con useMemo.
  - Suma todas las cantidades del carrito.

useCart()
  - Hook auxiliar para consumir el contexto.
  - Lanza un error si se usa fuera de CartProvider.


11.2 OrderContext.tsx
---------------------
Gestiona el proceso de checkout, el borrador de orden y las ordenes finalizadas.

Estados principales:
- orderDraft: OrderDraft | null
- completedOrders: FinalizedOrder[]

Persistencia local:
- megasport-order-draft
- megasport-orders

Funciones expuestas:

startOrder(data)
  Recibe:
  - subtotalAntesDelEnvio
  - detalles

  Procesamiento:
  - Crea un id temporal con crypto.randomUUID().
  - Inicializa direccion/destino vacios.
  - Inicializa courier y tarjeta en null.
  - Estado de pago inicial: PENDIENTE.
  - Total inicial = subtotal.

  Salida:
  - Guarda un nuevo OrderDraft.

updateShippingData(data)
  Recibe:
  - direccionDeEnvio
  - codigoDelDestino

  Procesamiento:
  - Actualiza direccion y destino.
  - Invalida cualquier courier anterior.
  - Reinicia costo de envio a 0.
  - Restablece total al subtotal.

selectCourier(data)
  Recibe:
  - idCourier
  - costoEnvio

  Procesamiento:
  - Guarda el courier.
  - Calcula total = subtotal + costoEnvio.
  - Reinicia datos de pago porque un cambio de courier cambia el monto final.

registerPaymentResult(data)
  Recibe:
  - idTarjeta
  - estadoDePagado
  - numAutorizacion

  Salida:
  - Actualiza el borrador con el resultado del pago.

finalizeOrder(data)
  Recibe:
  - numeroEnvio
  - estadoEnvio

  Validaciones:
  - Debe existir orderDraft.
  - El pago debe estar APROBADO.
  - Deben existir courier, tarjeta y numero de autorizacion.

  Procesamiento:
  - Genera un id local de orden tipo ORD-...
  - Copia los datos del borrador a FinalizedOrder.
  - Agrega numEnvio y estadoEnvio.
  - Inserta la orden al inicio de completedOrders.
  - Elimina orderDraft.

  Salida:
  - FinalizedOrder creada, o null si falla una validacion.

updateOrderShippingStatus(orderId, estadoEnvio)
  - Busca la orden finalizada por id.
  - Sustituye su estadoEnvio.

clearOrderDraft()
  - Elimina el borrador actual.

useOrder()
  - Hook auxiliar para acceder al contexto.


12. CARPETA src/services
------------------------
Contiene la logica que simula integraciones externas.
Esta carpeta sera uno de los principales puntos de cambio cuando exista backend real.

12.1 cardService.ts
-------------------
Funciones principales:

identificarTarjetaPorNumero(numeroTarjeta)
  Entrada:
  - numeroTarjeta como string.

  Procesamiento:
  - Elimina caracteres que no sean digitos.
  - Lee el primer digito.
  - Consulta cardPrefixMap.
  - Busca un proveedor activo con ese identificador.

  Salida:
  - CardProvider encontrado, o null.

autorizarPago(request)
  Entrada:
  - PaymentAuthorizationRequest.

  Procesamiento actual:
  - Simula latencia de red con wait().
  - Detecta el proveedor.
  - Si no existe, devuelve DENEGADO.
  - Para la simulacion, si el ultimo digito de la tarjeta es PAR se aprueba.
  - Si es IMPAR se deniega.
  - Si aprueba genera un numero AUTH-...

  Salida:
  - PaymentAuthorizationResult.

Reemplazo futuro:
- El frontend debera llamar al backend MegaSport.
- El backend determinara el proveedor, consultara la entidad Tarjeta de la BD y usara host + scriptAutorizacion para comunicarse con el servicio externo real.


12.2 courierService.ts
----------------------
Simula tres operaciones distintas del Courier:
- Cotizacion/cobertura.
- Creacion de envio.
- Consulta de estado.

Funciones auxiliares:

wait(ms)
  - Simula latencia de red.

calculateMockZone(codigoDestino)
  - Convierte el codigo de destino en una zona ficticia de 1 a 22.
  - Solo existe para obtener costos distintos en la simulacion.

consultarCourier(courier, codigoDestino)
  Entrada:
  - Courier.
  - codigoDestino de 5 caracteres.

  Procesamiento:
  - Simula espera.
  - Valida que el courier este activo.
  - Valida longitud de destino.
  - Aplica reglas locales de cobertura y costo.

  Salida:
  - CourierQuote con cobertura, costo y mensaje.

consultarTodosLosCouriers(codigoDestino)
  Entrada:
  - codigoDestino.

  Procesamiento:
  - Filtra couriers activos.
  - Usa Promise.all para consultar todos en paralelo.

  Salida:
  - CourierQuote[].

getMockShipments()/saveMockShipments()
  - Leen y guardan envios simulados en localStorage.
  - Llave: megasport-mock-shipments.

solictarEnvio(courierId, request)
  NOTA: el nombre actual de la funcion en el codigo es "solictarEnvio". Conviene renombrarla a "solicitarEnvio" antes de la integracion final.

  Entrada:
  - courierId.
  - ShipmentRequest con id temporal, destino y direccion.

  Procesamiento:
  - Busca courier activo.
  - Valida codigo de destino.
  - Genera un numero ENV-...
  - Guarda un envio simulado con fecha de creacion.

  Salida:
  - ShipmentCreationResult con estado inicial 1.

consultarEstadoEnvio(courierId, numeroEnvio)
  Entrada:
  - courierId.
  - numeroEnvio.

  Procesamiento actual:
  - Busca el envio en localStorage.
  - Calcula segundos transcurridos.
  - Cada 10 segundos avanza un estado hasta un maximo de 5.

  Salida:
  - ShipmentStatusResult.

Reemplazo futuro:
- Estas funciones deberan llamar al backend MegaSport.
- El backend obtendra host y scripts del Courier guardado en la base de datos.
- El backend llamara los Web Services reales de Envios Expresso, Entregas Rapiditas o Winnie Express.


13. CARPETA src/pages

13.1 Home.tsx
-------------
Pagina principal.

Responsabilidades:
- Hero principal de MegaSport.

13.2 Category.tsx
-----------------
Catalogo de una categoria.

Entrada:
- Parametro :category de la URL mediante useParams().

Procesamiento:
- Convierte el slug a un titulo legible.
- Filtra products por categoria y activo.
- Para cada producto calcula disponibilidad buscando variantes activas con stock > 0.

Salida:
- Lista de ProductCard.
- Mensaje si no existen productos.


13.3 ProductDetail.tsx
----------------------
Detalle y seleccion de variante.

Entrada:
- :id de la URL.

Procesamiento:
- Busca el producto activo con ese id.
- Obtiene colores unicos de variantes activas.
- Cuando se selecciona un color, filtra las tallas disponibles para ese color.
- selectedVariant representa la combinacion exacta de color + talla.
- La cantidad no puede superar stock.

Funciones principales:
- handleColorSelection(color): cambia color, reinicia talla y cantidad.
- handleSizeSelection(size): cambia talla y reinicia cantidad.
- increaseQuantity(): incrementa si hay stock.
- decreaseQuantity(): disminuye hasta minimo 1.
- handleAddToCart(): llama addItem(idVariante, cantidad, stock).

Salida:
- Informacion del producto.
- Selector de color/talla.
- SKU y stock.
- Selector de cantidad.
- Boton para agregar al carrito.


13.4 Cart.tsx
-------------
Pantalla del carrito.

Datos de entrada:
- items desde CartContext.
- products desde data/products.

Procesamiento:
- detailedItems reconstruye Product y ProductVariant a partir de idVariante.
- subtotal suma product.precio * item.cantidad.

Funciones:
- updateQuantity: proviene de CartContext.
- removeItem: proviene de CartContext.
- clearCart: vacia carrito.
- handleContinuePurchase(): convierte el carrito en detalles de orden, llama startOrder() y navega a /checkout.

Datos creados al continuar:
- idVariante
- cantidad
- precioPorUnidad
- subtotalAntesDelEnvio

Salida:
- Lista de items, cantidades, subtotales y resumen.


13.5 Checkout.tsx
-----------------
Captura los datos de entrega.

Entrada:
- orderDraft desde OrderContext.

Estado local:
- direccion
- codigoDestino

Validaciones actuales:
- codigoDestino debe tener exactamente 5 caracteres.
- direccion debe tener mas de 5 caracteres.

handleSaveShipping()
  - Guarda direccion y codigo con updateShippingData().
  - Navega a /checkout/courier.

Tambien reconstruye los detalles para mostrar un resumen de compra.


13.6 CourierSelection.tsx
-------------------------
Consulta y seleccion de courier.

Entrada:
- orderDraft, especialmente codigoDelDestino.

Estado local:
- quotes
- loading
- error
- selectedCourier

Funciones:

consultarCouriers()
  - Llama consultarTodosLosCouriers(codigoDestino).
  - Maneja loading/error.
  - Guarda CourierQuote[].

useEffect()
  - Ejecuta la consulta automaticamente al entrar a la pantalla.

handleSelectCourier(quote)
  - Rechaza opciones sin cobertura o costo.
  - Guarda courier seleccionado en estado local.
  - Llama selectCourier() del contexto.

handleContinuePayment()
  - Si existe una cotizacion seleccionada navega a /checkout/pago.

Salida:
- Opciones de Envios Expresso, Entregas Rapiditas y Winnie Express.
- Cobertura/costo.

13.7 Payment.tsx

16. QUE DEBE CAMBIAR AL IMPLEMENTAR EL BACKEND
----------------------------------------------
La interfaz visual puede mantenerse en gran medida.

Cambios principales esperados:

1. products.ts
   Dejara de ser la fuente principal.
   Los productos y variantes se obtendran desde endpoints del backend.

2. CartContext
   Puede conservar estado visual, pero el carrito persistente debera sincronizarse con las tablas Carrito y articulo_en_carrito.

3. OrderContext
   OrderDraft puede seguir sirviendo como estado de interfaz, pero la orden real debera formalizarse con transacciones del backend y base de datos.

4. courierService.ts
   Debe dejar de calcular zonas/precios localmente.
   Debe llamar al backend.
   El backend consultara la tabla Courier y luego los Web Services de los otros grupos.

5. cardService.ts
   Debe dejar de aprobar por ultimo digito par/impar.
   Debe llamar al backend.
   El backend elegira el proveedor por prefijo, obtendra host/script de Tarjeta y realizara la autorizacion real.

6. Orden final
   El id no debe generarse en el navegador.
   Debe generarlo la base de datos o backend.

7. Stock
   La validacion definitiva y decremento de stock deben ejecutarse en backend, idealmente dentro de una transaccion.
   El frontend solamente debe mostrar la informacion recibida.

8. Precios
   El backend no debe confiar en precios enviados por el navegador.
   Al crear la orden debe leer el precio actual de Producto desde la base de datos y copiarlo a Detalle_orden.Precio_por_unidad.

9. Usuario
   Todavia no existe implementacion de registro/login/roles/administracion en este frontend.
   Se agregara junto con el backend segun la entidad Usuario y los CRUD requeridos.

10. CRUD administrativo
   Todavia no estan implementadas pantallas de mantenimiento para productos, variantes, categorias, usuarios, couriers o tarjetas.
   Son parte de una fase posterior.
