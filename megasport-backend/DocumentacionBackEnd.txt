Esta de aqui es la documentacion de BackEnd para lo que llevo el BackEnd usa:
- Express para servidor HTTP y API
- PG para conexion directa con PostgreSQL (que es lo que se usa en la base de datos)
- Cors para hacer llamadas desde React (FrontEnd)
- DotENV para variables privadas como la contraseña de la base de datos
- SupaBase como base de datos externa para la tienda (PostgreSQL)

Las carpetas que componen src son:
- Routes para guardar las URL disponibles (E.g GET /api/productos)

- Controllers para recibir las solicitudes HTTP y ver que hacer (E.g GET /api/productos -> productoController)

- Services contiene logica importante para cosas como consultar couriers, autorizar tarjeta, crear orden, actualizar inventario, etc.

- Config es para la configuracion general (en especial la de la base de datos)

- types son para interfaces TypeScript compartidas

5. CONEXION CON SUPABASE / POSTGRESQL
-------------------------------------

Inicialmente se intento usar Direct connection de Supabase.

En la red de desarrollo se produjo:

getaddrinfo ENOTFOUND

La conexion Direct usa IPv6 por defecto. La solucion aplicada fue cambiar a:

Session pooler

manteniendo el tipo URI y reemplazando DATABASE_URL por la cadena entregada
por Supabase para ese metodo.

La conexion actual funciona correctamente mediante pg.

11. src/services/catalogService.ts
----------------------------------

11.1 createSlug(value)

Convierte nombres de categoria a slugs:

Hombre  -> hombre
Mujer   -> mujer
Niños   -> ninos
Zapatos -> zapatos

Usa normalize('NFD'), elimina diacriticos, convierte a minusculas, aplica
trim() y reemplaza espacios por guiones.


11.2 getCategories()

Ejecuta:

SELECT id, nombre
FROM categoria
ORDER BY id;

Luego agrega slug con createSlug().

Salida:
Promise<Category[]>


11.3 ProductDatabaseRow

Tipo interno usado para representar cada fila devuelta por SQL antes de
mapearla a Product.

precio se recibe como string porque pg puede devolver NUMERIC/DECIMAL de esa
forma para evitar perdida de precision.


11.4 mapProduct(row)

Transforma ProductDatabaseRow a Product.

Procesamiento principal:
- Number(row.precio)
- createSlug(row.categoriaNombre)
- variantes ?? []


11.5 getProducts(categoryName?)

Usa:
- producto
- categoria
- variante_producto

INNER JOIN categoria:
- Cada producto debe pertenecer a una categoria.

LEFT JOIN variante_producto:
- Permite mantener el producto aunque no tenga variantes activas.

La condicion v.activo = TRUE se coloca dentro del ON del LEFT JOIN para
incluir solo variantes activas sin eliminar productos sin variantes.

p.activo = TRUE:
- Solo muestra productos activos.

Filtro opcional:

($1::TEXT IS NULL OR c.nombre = $1)

Si $1 es NULL no filtra categoria.
Si $1 es "Hombre", solo devuelve esa categoria.

Se usan parametros $1 en vez de concatenar valores directamente al SQL.


12. CONSTRUCCION DE VARIANTES EN JSON
-------------------------------------

JSON_BUILD_OBJECT()
- Convierte cada fila de variante en un objeto JSON.

JSON_AGG()
- Junta varias variantes en un arreglo.

FILTER (WHERE v.id_variante IS NOT NULL)
- Evita generar una variante falsa llena de NULL.

COALESCE(..., '[]'::JSON)
- Devuelve [] cuando no existen variantes.


13. GROUP BY
------------

Como JSON_AGG es una funcion de agregacion, la consulta agrupa por las
columnas de producto y categoria.

Conceptualmente:

Producto 1 | Variante 1
Producto 1 | Variante 2
Producto 1 | Variante 3

se convierte en:

Producto 1 | [Variante 1, Variante 2, Variante 3]


14. ALIASES Y FORMATO
---------------------

Se usan aliases como:

p.url_img AS "urlImg"
c.id AS "categoriaId"
c.nombre AS "categoriaNombre"

Las comillas conservan camelCase exactamente.

TO_CHAR() transforma creado_en a texto con formato:

YYYY-MM-DDTHH24:MI:SS


15. getProductById(id)
----------------------

La consulta es similar a getProducts(), pero usa:

WHERE
    p.id = $1
    AND p.activo = TRUE

Recibe [id] como parametro.

Si result.rows.length === 0:
- devuelve null.

Si existe:
- toma result.rows[0].
- ejecuta mapProduct().
- devuelve Product.


16. CONTROLLERS
---------------

categoryController.ts

listCategories:
- Recibe GET /api/categorias.
- Llama getCategories().
- Devuelve JSON.
- Responde 500 ante un error inesperado.


productController.ts

listProducts:
- Lee req.query.categoria.
- Busca el slug dentro de las categorias.
- Devuelve 400 si la categoria no existe.
- Convierte slug al nombre real de la BD.
- Llama getProducts(categoryName).
- Devuelve Product[].

Ejemplo:

ninos -> Niños -> getProducts("Niños")

getProduct:
- Lee req.params.id.
- Lo convierte con Number().
- Valida entero mayor que 0.
- Llama getProductById(id).

Respuestas:
- 400 ID invalido.
- 404 producto inexistente.
- 200 producto encontrado.
- 500 error inesperado.
